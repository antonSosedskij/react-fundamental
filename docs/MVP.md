# Помодоро-таймер: план MVP

Nov 2, 2026 · @Anton · ред. 2

## Цель и рамки MVP

MVP — помодоро-таймер в браузере с тремя режимами, настройками и статистикой за сегодня и 7 дней, без бэкенда. Проект учебный: он должен прокачать стейт, редьюсер, эффекты, рефы, Context и производное состояние.

**Разделение работы.** Каркас готов (этап 0): проект, тулинг, структура папок, типы, заглушки и тесты-спецификации. Логику и компоненты вы пишете сами. Тесты — это ТЗ: этап закрыт, когда его тесты зелёные.

**Входит:** таймер с режимами «фокус / короткий перерыв / длинный перерыв», управление, звук и заголовок вкладки, настройки, статистика в localStorage, горячие клавиши.

**Не входит:** бэкенд и авторизация, роутинг, уведомления браузера, PWA, темы оформления, задачи и проекты внутри помодоро.

## Функциональные требования

**Таймер**

- Три режима: фокус (25 мин), короткий перерыв (5 мин), длинный перерыв (15 мин).
- Длинный перерыв после каждого 4-го завершённого фокуса; число задаётся в настройках.
- Кнопки: старт, пауза, сброс, пропуск. Ручное переключение режима табами.
- Остаток вычисляется от метки окончания (`endsAt - Date.now()`), а не уменьшением счётчика. Иначе таймер отстаёт в фоновой вкладке.
- Отображение округляется вверх до секунды: сразу после старта видно `25:00`, а не `24:59`.
- Прогресс и номер помодоро — производные значения, в стейте не хранятся.

**Сигналы**

- Заголовок вкладки: `12:34 · Фокус`.
- По окончании интервала — звук; переход к следующему режиму автоматический, автостарт — по настройке.
- Горячие клавиши: `Space` — старт/пауза, `R` — сброс, `S` — пропуск. Не срабатывают при фокусе в `input`, `textarea`, `select` или `contenteditable`.

**Настройки**

- Длительности трёх режимов (1–90 мин), интервал длинного перерыва (2–10), автостарт перерывов, автостарт фокуса, звук.
- Хранятся в Context и localStorage; форма на контролируемых инпутах с валидацией. Лимиты — `SETTINGS_LIMITS`.
- Новые настройки применяются сразу, если таймер в `idle`. Если идёт или стоит на паузе интервал, он доживает со старой длительностью, а новые действуют со следующего.

**Статистика**

- Каждый завершённый фокус записывается как сессия `{ id, endedAt, durationMs }`. Пропущенные не записываются вообще — это гарантирует место записи, а не фильтр.
- `endedAt` берётся из `endsAt` таймера, а не из момента, когда сработал `COMPLETE` (вкладка могла спать).
- Показатели: помодоро и минуты за сегодня, столбики за 7 дней, серия дней подряд. Если сегодня ещё ничего нет, серия считается до вчера — она не прерывается, пока день не кончился.
- Дни — локальные календарные. Минуты — `Math.round(сумма мс / 60 000)`.
- Все показатели вычисляются из списка сессий; агрегаты не хранятся.

## Состояния таймера

`timerReducer(state, action)` — чистая функция без `Date.now()`: текущее время приходит в действии.

```ts
type Mode = 'focus' | 'shortBreak' | 'longBreak'
type Status = 'idle' | 'running' | 'paused'

interface TimerState {
  mode: Mode
  status: Status
  endsAt: number | null // метка окончания, когда running
  remainingMs: number // остаток, когда idle или paused
  completedFocusCount: number // для расчёта длинного перерыва
  settings: TimerSettings // снимок: длительности, интервал, автостарт (без звука)
}
```

Начальное состояние — `createInitialTimerState(settings)`, передаётся третьим аргументом в `useReducer`.

| Действие                      | Допустимо из | Результат                                                                                                                                           |
| ----------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `START { now }`               | idle, paused | `running`, `endsAt = now + remainingMs`                                                                                                             |
| `PAUSE { now }`               | running      | `paused`, `remainingMs = max(0, endsAt - now)`, `endsAt = null`                                                                                     |
| `RESET`                       | любой        | `idle`, полная длительность текущего режима                                                                                                         |
| `COMPLETE { now }`            | running      | следующий режим (`getNextMode(state, 'complete')`) в `idle`, или `running` с `endsAt = now + длительность` при автостарте; после фокуса счётчик + 1 |
| `SKIP`                        | любой        | следующий режим (`getNextMode(state, 'skip')`) в `idle`, без автостарта, счётчик не растёт                                                          |
| `SWITCH_MODE { mode }`        | любой        | указанный режим в `idle` с полной длительностью; счётчик не меняется                                                                                |
| `APPLY_SETTINGS { settings }` | любой        | снимок заменяется; в `idle` пересчитывается `remainingMs`, иначе текущий интервал не трогается                                                      |

**Следующий режим:**

- после любого перерыва — фокус;
- после завершённого фокуса — длинный перерыв, если `(completedFocusCount + 1) % longBreakInterval === 0`, иначе короткий;
- после пропущенного фокуса — всегда короткий.

Действие из недопустимого статуса возвращает **тот же объект** стейта (тесты проверяют `toBe`): так React пропускает ререндер.

**Где живут побочные эффекты.** Звук и запись сессии делаются там, где вызывается `dispatch({ type: 'COMPLETE' })` — в том же обработчике, по данным стейта до перехода. Не в `useEffect`, который следит за `mode`. Так же `APPLY_SETTINGS` вызывается из обработчика сабмита формы настроек, а не эффектом «настройки поменялись → диспатч».

## Структура проекта

Облегчённый Feature-Sliced Design: `app → pages → widgets → features → entities → shared`, импорт только сверху вниз, у каждого слайса публичный API через `index.ts`. Импорт в обход `index.ts` запрещён (кроме `@x`).

```text
src/
  main.tsx
  app/
    App.tsx                          # сборка провайдеров и страницы
    providers/SettingsProvider.tsx   # SettingsContext.Provider + useLocalStorage
    providers/SessionsProvider.tsx   # SessionsContext.Provider + useLocalStorage
    styles/global.css
  pages/home/                        # компонует два виджета
  widgets/
    timer-panel/                     # useReducer таймера, дисплей, управление, табы, хоткеи
    stats-panel/                     # сегодня, 7 дней, серия
  features/
    timer-controls/  mode-switcher/  settings-form/
    hotkeys/lib/useTimerHotkeys.ts
  entities/
    timer/
      model/{types, constants, timerReducer, selectors}.ts  + тесты
      ui/TimerDisplay.tsx
    settings/
      model/{types, defaults, settingsContext}.ts           # Context и useSettings — здесь
      @x/timer.ts                    # кросс-импорт TimerSettings для entities/timer
    session/
      model/{types, stats, sessionsContext}.ts + stats.test.ts
  shared/
    lib/hooks/{useLocalStorage, useNow, useDocumentTitle}.ts
    lib/time/formatDuration.ts + тест
    ui/Button/
    assets/sounds/                   # сюда положить bell.mp3
  test/setup.ts                      # jest-dom + cleanup для RTL
```

Два решения, которые FSD навязывает:

- **Context живёт в entity, провайдер — в app.** Фичам нужен `useSettings`, а импортировать из `app` они не могут.
- **Сессии — общий контекст.** Пишет их `timer-panel`, читает `stats-panel`; виджеты друг друга импортировать не могут, поэтому список поднят в `SessionsProvider`.

FSD для такого приложения избыточен, но это осознанная тренировка.

Подсказки к этапу 3:

- `COMPLETE` идемпотентен: из не-`running` он ничего не делает. Это спасает от двойного вызова в StrictMode.
- Тик чаще секунды нужен из-за дрейфа `setInterval`: при ровно 1000 мс секунды иногда перескакивают (`12:34 → 12:32`).

На каждом этапе дописывайте [docs/angular-to-react.md](angular-to-react.md).

## Критерии готовности MVP

- [ ] `npm test` зелёный, включая все тесты-спецификации.
- [ ] Полный цикл «4 фокуса → длинный перерыв» проходит с автостартом и без него.
- [ ] Таймер не отстаёт после 10 минут в фоновой вкладке (сверить с системными часами).
- [ ] Пауза и возобновление не теряют и не добавляют время.
- [ ] Перезагрузка страницы сохраняет настройки и статистику.
- [ ] Пропущенные интервалы не попадают в статистику.
- [ ] Смена настроек во время интервала не ломает текущий интервал.
- [ ] Горячие клавиши работают и не мешают вводу в форме настроек.
- [ ] В стейте нет значений, которые можно вычислить (прогресс, агрегаты, следующий режим).
- [ ] Нет `useEffect`, который только синхронизирует один стейт с другим или диспатчит в ответ на изменение стейта.
- [ ] `lint`, `typecheck`, `test` и `build` проходят без ошибок и предупреждений.
